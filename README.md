# Обработка высокоскоростной съёмки капель

Перенос MATLAB-обработки на Python. Три стадии, каждая — отдельный скрипт:

| Скрипт | Что делает | MATLAB-оригинал |
|---|---|---|
| `main/st1_droplets_separation.py` | убирает рим и брызги, находит капли, считает PIV и скорость в центрах капель | `st1_droplets_separation.m` |
| `main/st2_ptv.py` | связывает капли соседних кадров в траектории (PTV) | `st2_PTV_mod2.m` |
| `main/st4_droplets_in_area.py` | средние положение, скорость и размер капель в областях поиска | `st4_202210_droplets_in_area.m` |

Подробное описание каждой стадии — в начале её скрипта.

## Установка (один раз)

### Способ 1 (рекомендуется): uv

1. Установить [uv](https://docs.astral.sh/uv/) — менеджер Python и библиотек. Например, в PowerShell:
   `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`.
2. В папке проекта выполнить `uv sync`. Появится папка `.venv` с Python 3.12 и нужными
   библиотеками (их список — в `pyproject.toml`), и файл `uv.lock` с их точными версиями.

Команды запуска ниже — для этого способа: `.venv\Scripts\python.exe …`.

### Способ 2: обычный Python и pip (например, чтобы запускать из IDLE)

1. Установить Python 3.12 или новее с [python.org](https://www.python.org/downloads/).
2. Поставить библиотеки одной командой (в командной строке Windows):
   ```
   py -m pip install numpy==2.5.3 scipy==1.18.1 scikit-image==0.26.0 pillow==12.3.0 openpyxl==3.1.5 matplotlib==3.11.2 pyside6-essentials==6.12.0 pyqtgraph==0.14.0
   ```
   С этими версиями проверено совпадение с MATLAB. С другими версиями всё работает, но в редких
   пограничных случаях могут отличаться последние знаки.

   | Библиотека | Для чего |
   |---|---|
   | numpy | массивы и вычисления |
   | scipy | морфология, БПФ, интерполяция, чтение и запись .mat |
   | scikit-image | обработка изображений (заливка, нумерация объектов) |
   | pillow | чтение кадров (jpg, png, tif, bmp) |
   | openpyxl | чтение и запись таблицы записей xlsx |
   | matplotlib | картинки и окно просмотра |
   | pyside6-essentials | окна приложения (Qt) |
   | pyqtgraph | быстрый показ кадров в приложении |

   По желанию: `py -m pip install pytest` — для тестов, `py -m pip install pypandoc-binary` — для
   пересборки Word-версий документации.
3. Запуск — вместо `.venv\Scripts\python.exe` везде ниже писать `py`:
   - из **IDLE**: File → Open → `main\st1_droplets_separation.py` → Run → Run Module (F5); так же
     `main\st2_ptv.py`, `main\st4_droplets_in_area.py`, `tools\st1_viewer.py`, `app\run.py`. Из какой папки
     запущен IDLE, неважно: скрипты сами находят папки `lib` и `experiments`;
   - из **командной строки** в папке проекта: `py main\st1_droplets_separation.py` и т. д.;
     тесты — `py -B -m pytest`, Word-версии документации — `py tools\make_docx.py`.

   Запуск из IDLE пока не проверялся. Окно просмотра (`tools\st1_viewer.py`) и приложение (`app\run.py`)
   считают кадры в нескольких процессах — если из IDLE они поведут себя странно, запустите их из командной
   строки.

## Как запустить

1. В `experiments/current.py` указать эксперимент (имя папки в `experiments/`).
2. Проверить его `settings.py`: пути к картинкам, таблице записей и папке результатов, какие записи
   обрабатывать.
3. По очереди запустить из папки проекта:
   ```
   .venv\Scripts\python.exe main\st1_droplets_separation.py
   .venv\Scripts\python.exe main\st2_ptv.py
   .venv\Scripts\python.exe main\st4_droplets_in_area.py
   ```
   Каждая стадия берёт результат предыдущей из папки результатов. Скрипты пишут ход работы
   в консоль; ошибка в одной записи не останавливает остальные.

То же можно делать в приложении (ниже, вкладка «Запуск»): отметить записи и стадии и нажать «Запустить».

## Приложение: записи, таблица, пороги, запуск стадий, результаты

```
.venv\Scripts\python.exe app\run.py
```
Окно для эксперимента из `experiments/current.py`. Другой можно выбрать в списке вверху окна (`current.py`
при этом не меняется); кнопка «Сделать текущим» записывает выбранный в `current.py` — тогда его обрабатывают
и скрипты `main/`. Вкладки: «Записи», «Запуск», «Результаты».

### Вкладка «Записи»

* **Слева** — все записи таблицы: «Готова» (✓ — заданы диапазон кадров, `rim` и центр `c_x`, `c_y`;
  иначе — чего не хватает) и есть ли результаты st1, st2, st4. Несохранённые правки — «*».
  Можно выделить несколько записей (Ctrl, Shift) — тогда правка поля справа применяется ко всем.
* **В середине** — все кадры записи (не только диапазон). Номер кадра — номер файла, как `start_frame`
  и `fin_frame` в таблице. Шкала под кадром: зелёным — диапазон, синим — текущий кадр, серыми рисками —
  уже посчитанные кадры; щелчок по шкале — переход. Виды `1`–`5` — как в окне просмотра st1 (ниже).
  Кнопки «Начало = этот кадр», «Конец = этот кадр»; «Центр затравки» — нажать и щёлкнуть по кадру:
  `c_x`, `c_y` (px с 1) выделенных записей; крестик на кадре — заданный центр.
* **Справа, вкладка «Таблица»** — все колонки таблицы (описание колонки — во всплывающей подсказке).
  У пустого поля — кнопка «← значение» предыдущей заполненной записи: нажать её (или Enter в пустом
  поле) — принять.
  «Как у предыдущих» — заполнить пустые поля колонками, одинаковыми во всех заполненных записях (например,
  `rim`, `c_x`, `c_y`). Под `rim` — ползунок: кадр сразу пересчитывается с новым порогом (вид `2` —
  закрашенное сиреневым, вид `3` — найденные капли).
  **«Сохранить в таблицу»** пишет в xlsx только изменённые ячейки, остальное (форматирование, другие
  ячейки) не трогает. Перед первой записью за сеанс копия таблицы кладётся в `<OUTPUT_DIR>\table_backups`.
  Если таблица открыта в Excel — окно скажет закрыть её и сохранить ещё раз.
* **Справа, вкладка «Настройки»** — все значения `settings.py` и `thresholds.py` эксперимента: подпись —
  имя и комментарий из файла, у чисел и пар чисел (например, `RIM_GRAY_RANGE`) — ползунки (от 0 до
  удвоенного значения; набранное число становится новой серединой). Правка сразу пересчитывает кадр —
  так пороги подбираются «на глаз». Пути вводятся без кавычек, кортежи и списки — как в файле, например
  `(-100, 0)`, `[(381, None, 1, 302)]`. Поиск — по имени или слову из комментария. **«Сохранить настройки»**
  меняет в файлах только значения изменённых строк — комментарии и остальное остаются; «Вернуть как
  в файлах» — забыть правки. Пока настройки не сохранены, скрипты `main/` работают со значениями из файлов.
* **Ctrl+S** («Сохранить» вверху окна) — сохранить и таблицу, и настройки. Пока не сохранено, файлы не
  меняются; при закрытии окна с правками оно спросит, сохранить ли.

Клавиши на «Записях»: `←` `→` — кадр (держать — быстро), `Пробел` — слайдшоу, `Home` `End` — первый/последний файл,
`PgUp` `PgDn` — запись, `1`–`5` — вид, `M` — капли MATLAB, `Esc` — отменить «центр затравки»,
`F5` — перечитать `settings.py`, `thresholds.py` и таблицу (несохранённые правки остаются). Колесо мыши —
увеличение, перетаскивание — сдвиг. Кадры с расчётом (виды 2–5) считаются в фоне на всех ядрах, кроме
одного: текущий — первым (около 1–2 с), потом весь диапазон записи.

### Вкладка «Запуск»
Отметить записи (флажки; «Отметить готовые» — все, у которых заданы диапазон кадров, `rim` и центр)
и стадии (st1, st2, st4 — идут по порядку: st2 берёт результат st1, st4 — результат st2), нажать
«Запустить». Записи считаются параллельно, по процессу на запись (сколько сразу — «Записей одновременно»;
по умолчанию все ядра, кроме одного); окно при этом не подвисает. Колонка «Ход» — что сейчас делается
с записью (например, «st1: кадр 12 из 83», «st4 ✓», ошибка), внизу — общий лог (то же, что скрипты пишут
в консоль). Ошибка в одной записи останавливает только её. «Остановить» — остановить всё сразу (прерванную
стадию стоит запустить заново: её файлы могут быть неполными).
Считается то же и так же, что скриптами `main/` (те же функции), с настройками и таблицей из файлов: если
есть несохранённые правки, окно предложит сохранить их перед запуском. Результаты — в `OUTPUT_DIR`,
в тех же папках и файлах. Одна запись clear water 3 (≈ 80 кадров) — несколько минут.

### Вкладка «Результаты»
Запись — в списке вверху (при открытии — текущая запись «Записей»; в скобках — какие результаты есть).
«Траектории (st2)» — картинка как `tracks.png`. «Области (st4)» — таблица `_all_stat.dat` (по строке
на область с траекториями); выбор строки — картинка области и таблица её `.dat` (по строке на траекторию).
Увеличение и сдвиг — панель под картинкой (лупа, крестик; домик — вернуть). «Папка st1 / st2 / st4» —
открыть папку результатов записи в проводнике; «Обновить» — перечитать (например, после запуска скриптов
`main/` из консоли).

## Просмотр кадров и подбор порогов st1

```
.venv\Scripts\python.exe tools\st1_viewer.py
```
Окно для записей текущего эксперимента. Виды:
`1` — исходный кадр; `2` — кадр без рима и воды (закрашенное подсвечено сиреневым);
`3` — капли (Python — красные круги, MATLAB — голубые, если задан `MATLAB_RESULTS_DIR`);
`4` — смещения PIV поверх кадра; `5` — PIV как в MATLAB (клетки — скорость в м/с, красные стрелки —
PIV, синие — скорость капель).

Клавиши: `←` `→` — кадр, если держать — слайдшоу; `Пробел` — слайдшоу пуск/стоп; `Home` `End` —
первый/последний кадр; `PgUp` `PgDn` — запись; `M` — капли MATLAB вкл/выкл. Увеличение — лупа на
панели окна. Кадры записи считаются заранее в фоне на всех ядрах, кроме одного (в заголовке —
«посчитано N из M»); полный st1 запускать не нужно.

Подбор порогов «на глаз»: поменять число в `thresholds.py`, сохранить, нажать `R` в окне —
запись пересчитается с новыми порогами. Когда картинка устраивает — запустить st1. Удобнее — в приложении
(выше): там пороги меняются ползунками на вкладке «Настройки» и сохраняются кнопкой.

Что рисуется и как считается — `lib/st1/preview.py`, окно, клавиши и слайдшоу — `tools/st1_viewer.py`.
Другой способ просмотра (серия PNG, видео, картинки во время st1) — новая короткая оболочка над
`preview.py`.

## Таблица записей (xlsx)

Первый лист; строка 1 — заголовки, строка 2 — описания (не читается), данные — с 3-й строки.

| Колонка | Что это | Нужна |
|---|---|---|
| `rec_name` | имя записи | всем |
| `images_path_side` | путь к кадрам относительно `IMAGES_DIR`; если не оканчивается именем записи, оно добавляется | всем |
| `cond_num` | номер условий (по нему можно выбирать записи: `CONDITIONS` в settings) | — |
| `start_frame`, `fin_frame` | диапазон кадров (номера файлов по порядку, с 1); без них запись пропускается | всем |
| `rim` или `rim_new` | порог площади рима и крупных брызг, px² | st1 |
| `cx` или `c_x`, `cy` или `c_y` | начало координат для st4, px | st4 |

## Результаты

Папки и файлы — с теми же именами и в тех же форматах, что у MATLAB:

```
<OUTPUT_DIR>/PIV/<путь записи>_output_st1_droplets/
    particles.mat                 капли по кадрам: centers_arr (x, y; px с 1), radii_arr (px),
                                  xd_q_arr, yd_q_arr (скорость PIV в центре, px/кадр)
    PIV_output_arr.mat            PIV по парам кадров
    PIV_output_filtered_arr.mat   PIV после фильтрации
<OUTPUT_DIR>/PTV/<путь записи>_output_st2_PTV/
    ptv_unfiltered.mat            траектории p_arr (колонки описаны в lib/st2/tracking.py)
    tracks.png                    траектории: длинные — синие, короткие — оранжевые,
                                  капли без траектории — красные
<OUTPUT_DIR>/st4/<путь записи>_output_st4/
    <область>.dat                 x мм, y мм, vx м/с, vy м/с, r мкм — по траектории на строку
    <область>.mat, <область>.png
    _all_stat.dat                 высота мм, нижний край мм, число траекторий, средние vx, vy, r
```
`.dat` — каждое число `%16.7e`, строки CRLF, как `save -ascii` в MATLAB.

## Отличия от MATLAB

Обработка повторяет MATLAB-скрипты, включая места исходного кода, которые выглядят как ошибки.
В коде они помечены `ВОПРОС К СПЕЦИАЛИСТУ (Qn)`; список с объяснениями, предлагаемыми
исправлениями и замерами того, как исправление меняет результат, — [QUESTIONS.md](QUESTIONS.md).

Известные расхождения с сохранёнными результатами MATLAB (из-за шума округления, не логики):
* st1, F40_1: на кадрах 68 и 77 — по одной пограничной капле (порог canny); в единичных ячейках PIV
  с двумя равными пиками корреляции выбирается другой пик.
* st2, 0203: у неподвижных капель решение зависит от шума округления ~1e-13 в MATLAB — часть
  траекторий отличается.
* Пороги st1 для clear water 3 не восстановлены (взяты из скрипта для v4_Zot_new).
