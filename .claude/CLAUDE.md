# CLAUDE.md — памятка для Claude Code

## Проект
Перенос MATLAB-обработки высокоскоростной съёмки капель на Python 3.12: st1 (удаление рима, PIV, поиск
капель), st2 (PTV-трекинг), st4 (статистика по областям поиска). Пользователь — исследователь, не
программист; общаться по-русски, кратко, простым языком.

* Исходники MATLAB: `D:\ИПФ РАН\Дмитрий\stage 2 new 7 new bag mod clear water 3` (`st1_droplets_separation.m`,
  `st2_PTV_mod2.m`, `st4_202210_droplets_in_area.m` + `_v1_function2.m`); внешние функции —
  `D:\ИПФ РАН\Дмитрий\Сашины проги`; ещё одна версия st1 — `D:\ИПФ РАН\шуриковские скрипты`.
  Код MATLAB — источник истины; `.m` в CP1251.
* Документация: `README.md` (запуск, настройки), `METHOD.md` (физика и математика), `CODE_GUIDE.md`
  (карта кода), `QUESTIONS.md` (вопросы к специалисту).
* Окружение: `.venv` (`uv sync`); тесты — `.venv\Scripts\python.exe -B -m pytest` (`-B` — без `__pycache__`);
  сравнение с MATLAB — `tests\compare_with_matlab.py`. Окно просмотра st1 — `tools\st1_viewer.py`.
* Архив старой версии — `D:\ИПФ РАН\project_старая_версия_2026-10-10.zip`.
* `rm` запрещён настройками — удалять просит пользователя (давать команды для Git Bash и PowerShell).
* Скрипты с процессами (ProcessPoolExecutor) запускать из файла, не через stdin: на Windows дочерние
  процессы не могут импортировать `<stdin>`.

## Правила пользователя
1. Никаких одноразовых и отладочных скриптов в проекте: эксперименты — inline или во временной папке
   вне проекта; перед сдачей — попросить удалить.
2. Код чище и понятнее MATLAB; пользователь судит по дереву проекта. Мало файлов, неглубокие папки,
   описание в начале каждого файла, никаких `__pycache__` и служебных прослоек.
3. Работает для любого эксперимента: ничего специфичного в коде — только в `experiments/<эксперимент>/`
   (`settings.py`, `thresholds.py` — только значения) и таблице записей xlsx. `main/` — скрипты стадий,
   не правятся; `lib/` — код по стадиям; `tools/` — вспомогательные инструменты.
4. Работоспособность доказывать: прогон на реальных данных (не одной записи) и тесты; явно говорить,
   что проверено, а что нет.
5. Перед изменениями во многих файлах — согласовать план.
6. Долгие задачи — `run_in_background`, вывод — в файл вне проекта; не ждать через `sleep`.
7. **При любом изменении кода обновлять документацию**: описание (docstring), таблицы `CODE_GUIDE.md`
   (функции — разд. 3, настройки — разд. 4), при изменении метода — `METHOD.md`. `tests/test_docs.py`
   проверяет описания и полноту таблиц. После правки любого .md пересобрать Word-версии:
   `.venv\Scripts\python.exe tools\make_docx.py` (папка `docx/`, pandoc из pypandoc-binary).

## Решения пользователя — соблюдать
1. Сомнительные места MATLAB (Q1–Q11, `QUESTIONS.md`) **не исправлять** — ждём специалиста. В коде
   помечены `ВОПРОС К СПЕЦИАЛИСТУ (Qn)`. Точные копии MATLAB-функций (триангуляция, polyfit,

2. Структура папок результатов (`PIV/<путь>_output_st1_droplets` и т. д.) и файлы .mat — как в MATLAB, пока
   Python-версия не подтверждена: их читают неперенесённые st3/PTV_analyze/st4_droplets_all.
3. Пороги st1 clear water 3 не менять без решения пользователя (что найдено — `QUESTIONS.md`).
4. Вспомогательные картинки: способ просмотра должен легко меняться — «что показывать»
   (`lib/st1/preview.py`) отдельно от «как показывать» (`tools/st1_viewer.py`).
